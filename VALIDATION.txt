Cinnaroids 2.1.0 — Windows x64
Validation snapshot: 2026-10-04

The GPUI launcher discovers the installed Cinnabar, registers its embedded
WASM component, and attaches to an existing matching client. It starts a
client only after the user presses Start Cinnabar and no matching process
is running. No operating-system input hooks remain.

Completed checks for live attachment:
- 15 launcher tests: installed/custom selection, process path matching,
  bounded registration, acknowledgment lifetime, metadata-based update
  retry, migrations, resource preservation, and independent preferences.
- Touched client, UI, renderer and component-host crates compile with tests
  and the opt-in local-mods feature against Cinnabar v0.1.5.
- The streamed-terrain lighting/mesh regression passes using its existing
  bounded asynchronous completion wait instead of a fixed polling count.
- 12 registration regressions: actual installation acknowledgment,
  identity-only state preservation, retained source snapshots, revocation,
  quarantine retry, stale generations, and retirement/backpressure ordering.
- All 44 host tests pass, including two prepared-persistence regressions:
  rejected initialization cannot write preferences, and accepted successors
  retain live settings without old retirement overwriting newer writes.
- The additional companion-symlink regression passes on Windows: writes
  replace the selected companion link without modifying its outside target.
- 4 input regressions: reservation, cursor restoration, focus handling,
  and discarding keyboard/mouse edges predating attachment.
- 3 real Inter Medium font fixture tests, 3 font replacement regressions,
  and the renderer's reserved-page upload regression pass.
- All 10 renderer texture-catalog tests and the client UI native font-byte
  budget regression pass with the dedicated font slot, including rejection
  of malformed dimensions, malformed payloads, and byte-budget overflow.

A fresh native Windows preview at 1280x720, DPI 1, GUI scale 2 verified
late font attachment after renderer startup, unloading, and reattachment.
Text remained legible, geometry and clipping were intact, and unloading
restored the game font without disturbing the panel. The fixture's known
background tonemapping/validation-layer diagnostics are not zero-warning
or release frame-budget acceptance evidence.

After integrating the current dev rendering model, a hidden GPU fixture
repeated late attachment, unloading, and reattachment at 1280x720, DPI 1,
GUI scale 2 without activating a window or sending desktop input. The
three rendered frames retained sharp Inter text, unchanged geometry and
clipping; unloading restored the separate game font.

The launcher was inspected natively at 600x360 in dark mode. Installed
client compatibility errors fit the card and the regular window controls
and layout remained intact.
The final --background build passed all 15 launcher tests, stayed alive
without a visible main window, and wrote the expected bounded registration
for the installed client without starting a game or sending desktop input.

Previously completed validation for the unchanged packaged guest:
- 28 guest tests: independent switches, click timing, aim selection,
  reach, settings normalization, emergency stop and key capture.
- The real packaged WASM passed the 100,000-fuel callback probe with no WASI.
- Earlier GPU previews passed at 1280x720/GUI 2, 2559x1439/GUI 3 (dark)
  and 1920x1080/GUI 4 (light), DPI 1. Live tabs, sliders and toggles worked.
- The README capture provenance is in assets/PROVENANCE.txt.

The guest SDK remains pinned to the merged personal-controls API at
7da8eac26deccbd0205059c1abecbe7a4702d2b0. Live registration changes no WIT
contract or guest code. Upstream live-attachment PR:
https://github.com/bedrock-mc/cinnabar/pull/94

Older installed clients require one update and normal restart. The private
one-time updater waits for normal game exit, verifies source/target hashes,
backs up the original executable, and replaces only that executable and
its build metadata. Existing resources, settings and other binaries remain.
The integration build retains the installed client's Tab player roster.
An installed-layout startup preflight loaded the existing prepared block,
atmosphere, entity, font, HUD, icon, localization, sound, JSON-UI, and physics
carriers. It then exited at the deliberately absent bridge endpoint before
opening a game session. This confirms resource compatibility, not live play.
The final v0.1.5 play/local-mods executable repeated that preflight headlessly
against the installed layout and reached the intended missing-core stop.
The installed executable was then replaced after normal game exit and its
SHA-256 verified against that build. The original v0.1.5 executable remains
in a verified backup. The updater's atomic swap also passed a file fixture.

Native physical Right Shift remains unverified: the automation tool's
Shift_R request produced ShiftLeft in an earlier run. The panel is bound
to ShiftRight. Connected multiplayer and release performance acceptance
have not been tested; current older running sessions cannot gain the loader
without a restart. A queued update is not a completed live attachment.
